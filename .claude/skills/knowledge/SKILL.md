# knowledge (横断ナレッジの保存)

プロジェクトを跨いで再利用できる知見・設計判断・調査結論を、`~/.claude/projects/_knowledge/` に 1 トピック 1 ファイルの md で保存する。Claude Code の自動メモリと同じ frontmatter + `[[wikilink]]` 形式(プレーンな md なので閲覧ツールは自由)。

## 2 モード

- **保存モード** `/knowledge <内容 or .agents/share のパス>` … その 1 件を判定して保存(昇格)
- **棚卸しモード** `/knowledge`(引数なし) … `.agents/share/` を走査して、1 件ずつ判定・昇格

## 保存先の振り分け(最初に判定)

このスキルは「横断で再利用できる知識」だけを `_knowledge/` に入れる。**入れる前に必ず宛先を判定**し、該当でなければ誤って入れず、正しい場所を提案する。宛先一覧は `docs/rules/refs/workflow/agent-storage.md` の「昇格 (promotion)」節に従う。

`_knowledge/` 該当分だけ「保存モードの手順」で保存する。skill 化・ルール化は勝手に作らず**提案・確認**まで。

## 自動発動(model invocation)

会話中に「後で再利用できそう」な内容が出たら、上の振り分けに照らして**一言提案する**(自動保存はしない):

- 横断ナレッジ(設計判断・トレードオフ結論・出典つき調査結論・運用ノウハウ・ハマりどころ) → `_knowledge/` に残すか提案
- 手続き / 案件ルール / 案件固有の事実っぽいもの → 該当先を提案(skill 化 / pj ルール / 自動メモリ)

提案は控えめに。雑談・一時的な作業ログ・未確定の検討メモは提案しない。**自動発動時は棚卸しモードを走らせない**(対象は目の前の 1 件のみ)。同意したら実行、断られたら何もしない。

## 保存先

- 保存先ルート: `~/.claude/projects/`(md 置き場。閲覧は任意のエディタで)
- 横断ナレッジ: `~/.claude/projects/_knowledge/<slug>.md`
- 索引: `~/.claude/projects/_knowledge/INDEX.md`(参照条件＋リンクの索引。無ければ作成)

## 保存モードの手順

1. 内容を確認(`.agents/share` 等のパスが渡されたら読み込む)。**振り分けで `_knowledge/` 該当か判定**し、該当でなければ該当先を提案して終了。自動発動時は保存可否を一言確認する。
2. 1 トピックに切り出し、`_knowledge/<slug>.md` を作成する(既存に該当があれば追記/更新し、重複を作らない)。
   - frontmatter: `title` / `tags` / `created`(YYYY-MM-DD、相対日付は絶対日付に変換) / `source`(あれば URL や PR 等) / `参照条件`(この知見を後で引くべき状況。recall 用)
   - 本文は簡潔に。関連ノートは `[[slug]]` で wikilink する(未作成リンクも可)。
3. `_knowledge/INDEX.md` に 1 行追記する(`- [[slug]] — 参照条件: <この知見を引くべき状況>`)。`_knowledge/` や `INDEX.md` が無ければ作成する — INDEX.md の冒頭に「各エントリの参照条件に該当する作業のときに本文を読む(全部は読み込まない)」旨＋「(任意) `~/.claude/projects/` を Obsidian で vault として開くと見やすい(手順: https://www.notion.so/3725fe8d887e816a8516ea079a1a81df )」を入れる。
4. 保存したファイルパスを報告する。

## 棚卸しモードの手順

`.agents/share` は「貯めて後でまとめて昇格する受け箱」(特に長時間/headless 実行用)。区切り(対話の締め)や headless 実行の末尾に走らせる。

1. `.agents/share/` の中身を列挙する(更新日とともに)。空なら「なし」と報告して終了。
2. 各アイテムを「保存先の振り分け」で分類する(`_knowledge/` / skill 化 / pj ルール / 自動メモリ / 破棄)。
3. 対話時は確認してから実行 / 自律(headless)実行時は自分で判断して実行する。`_knowledge/` 該当は保存モードの手順で保存、それ以外は該当先へ提案・誘導。
4. 昇格・破棄したものは `.agents/share/` から掃除する(gitignore なので残っても害はないが、受け箱は新鮮に保つ)。

## 制約

- 1 ファイル 1 トピック。長文の雑記は作らない。
- 機密情報(鍵・トークン・個人情報)は保存しない。
- 既存ノートと重複する場合は新規作成せず更新する。
