# 管理画面フロント(apps/web/app/admin/)

`apps/web/app/admin/` の管理画面フロント(一覧・詳細・フォーム等の CRUD 画面)を書く際の規約。

## 規範実装(暫定 / shake の mission を参照)

このレイヤーの規範実装は **entermotion-jp/shake**(GitHub MCP で参照)の admin の**ミッション系画面**とする。単一リソースでなく、ミッション系の画面群を横断して読み、リソース1件分のディレクトリ構成(一覧 / 詳細 / フォーム / 新規作成 / CSV ダウンロード等のファイル分割)・サーバ / クライアントコンポーネントの分担・データ取得と表示の分割・命名などのパターンに倣う。

- `apps/web/app/admin/(default)/mission-groups/`
- `apps/web/app/admin/(default)/mission-steps/`
- `apps/web/app/admin/(default)/mission-participations/`

なお、本テンプレ同梱の `apps/web/app/admin/(default)/{users,images,image-tags}/` は上記パターンに沿った CRUD 画面の実装例で、標準的な一覧 / 詳細 / 新規作成 / CSV ダウンロードはこれらを直接参照すればよい(この範囲では shake を参照する必要はない)。shake は、同梱画面にない構成(リソース間の絞り込み導線など)を補完するために参照する。

注意:

- **既存ルール優先**: 本 doc の各規約と shake 実装が食い違う場合は本 doc を優先する。shake は本 doc が触れていないパターンの実例・補完として参照する。
- **legacy は除く**: `@deprecated` 関数・未使用引数など規範としない旧コードが混在し得る。パターンに倣い、これらは複製しない。
- **暫定措置**: 別リポジトリへの外部参照は本来望ましくないが、現状の事実上の規範であるため暫定として記載する。
- **参照できない場合はユーザーに確認**: アクセス権等で shake を参照できないときは、推測で進めずユーザーに確認する。

## ユーザー詳細からミッション系画面への導線

shake では、ユーザー詳細(`users/detail.tsx`)からユーザー識別子(`customerNumber` 等)を query で渡し、そのユーザーで絞り込んだミッション系一覧へリンク遷移できる(遷移先の一覧側が query を読んで絞り込む)。ユーザーに紐づくリソースの一覧画面を追加する際は、この導線に倣い、ユーザー詳細側にも同様の絞り込みリンクを設ける。

## 識別子は ID でなく意味のある値で見せる

運用者(管理者)に見せる識別子は、内部 ID ではなくお客様番号・タイトル・属性など人間が理解・検索できる値に寄せる。ID はエンドユーザー(運用者を含む)にとって情報を持たない値で、本来意識させたくない。遷移やデータ連携の突合を ID で行うのは妥当だが、それはシステムが裏で担う処理であり、画面に ID を表示するのはなるべく避ける。

- **一覧**: ID 列を作らず、お客様番号・タイトル等の意味のある値を詳細へのリンクにする(ID は URL に載るだけ)。例: `users/data-table.tsx`
- **詳細**: 確認手段が一つも無いと困るため、保険として ID も表示してよい。例: `users/detail.tsx`
- **フォーム**: ユーザー等を手入力で指定する場合も、ID でなくお客様番号で指定できるのが望ましい。API が `userId` を要求するなら、お客様番号 → `userId` の解決をフロント / API 側で行う
- 画面間の導線で `userId` を query で引き継ぐなど、システムが裏で ID を渡すのは本方針と矛盾しない
