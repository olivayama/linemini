# ルール

`docs/rules/` 配下のルールを書く際のルール

## 基本原則

- **1ファイル200行以下にする**。長くなったらファイルを分割する
- **同じミスを繰り返したときだけルールを追加する**。事前に網羅しようとしない
- **具体的で検証可能な指示を書く**
- **削除しても AI がミスしないなら、削除する**。ルールの肥大化を防ぐ

## 書く場所

- **共通ルール (`general.md`)**: テンプレートから派生した全プロジェクトに適用するルール
- **固有ルール (`pj.md`)**: 特定のプロジェクトにのみ適用するルール
- **参照 (`refs/`)**: ルール本体から分割した詳細ドキュメント

## 書くべきこと

- アーキテクチャ判断や設計方針
- コーディング標準、命名規則
- ビルドおよびテストコマンド
- 一般的なワークフロー
- よくある落とし穴や非自明な動作

## 書くべきでないこと

- **linter/formatter で強制できること**: ESLint や Prettier に任せる
- **AI が既に知っていること**: npm, git, TypeScript の基本的な使い方など
- **稀なエッジケースの詳細**: 頻繁に発生するパターンに絞る
- **既存コードの重複**: コードをコピーせず、ファイルパスを参照する
- **自明なこと**: 「きれいなコードを書く」のような当たり前の指示は不要

## 構造化

- マークダウンの見出し (`#`, `##`) と箇条書きで整理する
- 関連する指示をセクションにグループ化する
- 具体例や参照ファイルを示す

## 矛盾を避ける

- ルールファイル間で矛盾する指示を作らない
- 新しいルールを追加する前に、既存ルールと競合しないか確認する
- 古くなったルールは削除する
